# Customer: справка по объектам

Здесь описаны данные и методы сервиса. Нужные изменения для ЛР1 перечислены в [TASK.md](TASK.md).
Часть методов уже реализована в заготовке, остальные добавляются по мере выполнения работ.

## Данные и поведение

`Customer` хранит сведения о клиенте и его состоянии обслуживания.

| Объект | Данные и назначение |
|---|---|
| `Customer(customer_id, name, category, online_consent=False)` | Клиент. Начальный статус — `ACTIVE`; категории — `STANDARD`, `PREMIUM`, `BUSINESS`. |
| `CustomerContext(operation_type, channel)` | Данные операции: `PURCHASE` или `CASH_WITHDRAWAL`, канал `POS` или `ONLINE`. Класс уже готов. |
| `CustomerService` | Находит клиента в хранилище и проверяет доступность операции. |

Методы `block()`, `activate()` и `close()` меняют статус клиента. Свойство статуса доступно только для чтения. Метод `availability() -> CheckResult` проверяет доступность без изменения объекта.

`CustomerService.check(customer_id, context) -> CheckResult` сначала вызывает `availability()`, затем проверяет дополнительные правила в заданном порядке. Проверку статуса нельзя отключить заменой правил.

Общий интерфейс правил — `CustomerEligibilityRule.check(customer, context) -> CheckResult`. `AllowedCategoryRule(categories)` проверяет категорию клиента, `AllowedOperationRule(operations)` — вид операции. Хранилище, классы входных данных, перечисления и исключения уже реализованы.

## Работа с готовым кодом

Обращение к сервису выполняется через `app/api.py`. Разрешённые файлы указаны в [TASK.md](TASK.md).
Проверки используют подготовленные данные и не зависят от работы других групп.

Функции `create`, `make`, `call` и `view` связывают готовый API с реализацией. Используемые ими функции сервисного модуля должны сохранять сигнатуры. Сам `app/api.py` не редактируйте.

До ЛР5 сборка предоставлена готовой. Нужные объекты могут создаваться в сервисном модуле; `assembly.py` менять не нужно.

## Ошибки и результаты

`DomainError` содержит код ошибки. При отказе проверки состояние объекта не должно меняться.
Ошибка переданной зависимости не заменяется успешным результатом. Конкретные коды и примеры
приведены в задании и открытых тестах.
